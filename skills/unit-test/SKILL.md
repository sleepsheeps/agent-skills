# 单元测试与对抗性测试工程规范（unit-test）

编写、加固或审查单测、集成测试与黑盒 E2E 测试时遵循本规范，目标不是“把主流程跑绿、把数字凑高”，而是**用最小、最稳的确定性用例精准拦住真实线上缺陷**。

## 1. 覆盖率双标准与反假绿铁律

- **覆盖率双标准（不唯总数字论）**：
  - **底线参考**：核心逻辑包语句覆盖率 **≥ 80%**，状态机/协议/路由/存储等高危核心包 **≥ 85%**。
  - **硬性红线**：逐函数排查所有含**状态转移、I/O、并发/锁、错误与恢复**的函数，做到 **0% 盲区清零**；绝不为了刷到 95%/100% 给简单 getter 写水测试。
- **“删修复必红”自检（Mutation Check）**：
  - 每条缺陷回归测试写完后，必须反推：**如果把刚写的那几行修复代码删掉，本用例是否 100% 必红？** 若删掉修复仍能通过，说明被兜底路径掩护了，属于假绿，必须重写。
- **独立因果隔离**：
  - 验证目标分支 B 时，必须关闭同样能触发预期结果的兜底分支 A（例如测“读取错误返回失败”时关闭普通流兜底，并断言精确错误 `errors.Is(err, os.ErrPermission)` 而非笼统 `err != nil`）。
- **禁止忽略测试内辅助调用的错误**：
  - `WriteFile`、`ReadResponse`、`ReadAll`、`json.Decode`、`WalkDir` 回调、清理断言等一律检查错误，绝不静默丢弃。
- **文本与指标精确断言**：
  - Prometheus 指标、JSON/日志输出须按完整指标名+标签或结构化反序列化精确校验，禁止用宽泛子串匹配（易误中同名/注释行）。

## 2. 六维对抗性用例设计清单

编写或加固测试时，按模块涉及的维度逐项排查，避免“只测顺路”：

### ① 状态 × 到达路径矩阵
- 同一状态转移存在多条触发入口时（如**事件通知 vs 定时全量扫描**、**在线运行 vs 停机重启恢复**、**首次调用 vs 重复调用 / 终态后再调用**、**组合位掩码事件**如 `Write|Remove`），必须做**状态 × 路径**组合覆盖，不能只测事件先到的“顺路”。
- 同时覆盖 **0 值 / 0 字节空对象 / 旧版升级缺字段记录** 与非空常规对象，防零值边界漏判。

### ② 真实物理尺度与资源上限
- **网络背压 / 限流 / 拒帧 / 截断**：必须使用**超过操作系统内核 TCP 缓冲（≥ 512 KiB ~ 4 MiB）**的真实大载荷，严禁用几 KB 小包测试（小包会完整塞入内核缓冲，掩盖写中途 `TCP RST / EPIPE` 读不到错误回执的问题）。
- **缓冲复用与高水位内存**：必测 **“大包尖峰 → 连续小包 → 双重 GC → 测量堆占用”**，验证内存真正回落而非永久滞留。
- **资源/句柄泄漏**：初始化失败、鉴权/校验拒绝等错误重试路径，循环执行 N 次并实测进程 FD 数（如 `/proc/self/fd`）或连接数增量 `== 0`。
- **精确边界 ±1**：对所有外部硬上限（如 Linux `NAME_MAX=255` 含追加后缀、协议头/JSON 响应上限、整型 `MaxInt64`/`uint32` 溢出、配置上下限 `min-1 / min / max / max+1`）做精确边界验证。

### ③ 确定性并发、锁与停机边界
- **禁止靠 `time.Sleep` 赌竞态窗口**：并发竞态、在途取消、排空与背压测试一律使用 `channel` 栅栏、`net.Pipe()`、阻塞钩子或可控假时钟精确钉死临界点，确保 `-race -count=2+` 100% 稳定、零抖动。
- **停机与取消三必测**：
  1. **不可打断阻塞（慢盘/黑洞）下的有界退出**：断言实际耗时接近单次 `timeout`，不无限挂死，也不出现多阶段预算叠加翻倍；
  2. **超时后恢复再调用**：验证排空/等待超时后重新放行不触发 `WaitGroup` 复用 panic 或状态反转；
  3. **本端取消/超时误差隔离**：调用方取消 `ctx` 或超时，必须还原返回 `ctx.Err()`（不把 `DeadlineExceeded` 吞成 `Canceled`），且**绝不计入远端健康失败计数或触发熔断/冷却/切流**。
- **零泄漏收尾**：涉及后台协程或文件锁的包，用例退出后必须验证无 goroutine 泄漏、无残留锁（再次加锁可立即成功）。

### ④ 调度公平、毒丸隔离与顺序一致性
- **三项夹击防饿死**：轮转/优先级调度必测 **“左热源 + 中间异类/大项 + 右热源”**，确认居中项在持续负载下不被永久饿死。
- **事件循环防饿死**：单协程批处理/发送循环必测在持续满载积压期间插入新事件、高优任务和取消信号，断言能在有界时间内响应。
- **毒丸隔离**：批处理/扫盘必测 **1 个非法或损坏项 + 1 个健康项共存**，断言毒丸跳过告警且健康项正常完成。
- **同源保序 + 异源隔离**：依赖追加顺序的归档/流水线必测 **早段失败 + 晚段就绪 + 另一健康源共存**（以及顶层扫目录/查库失败），断言同源绝不乱序抢跑、健康源不受阻塞，恢复后最终顺序严格正确。

### ⑤ 集群路由、切流与黑洞容错
- **测“不切流/不降级”必须配真备机**：验证 `BAD_REQUEST` / `RETRY_BUSY` 等不应切流场景时，必须启动 **≥ 2 个真实健康可绑定节点**，杜绝“本来就没备机可切”造成的假通过。
- **配置边界隔离**：测故障切流时，必须验证**已从配置/发现移出的历史缓存地址**即使被异身份占用，也绝不能被选为新目标。
- **发现对抗**：覆测**同源双栈/多 IP 去重 vs 跨源同 ID 冲突**，以及**少量快健康节点 + 多批挂起黑洞节点**下仍能保留健康结果完成绑定。

### ⑥ 配置、文件系统与时间边界
- **配置 fail-fast 矩阵**：必测默认值精确核对，以及**负值、0、未展开 `${VAR}`、缺端口/非法 `host:port`、空白串**；若某配置支持“空串关闭功能”，须补**运行态测试**证明真关闭而非静默绑定随机端口。
- **环境护栏与零副作用**：必测**缺失挂载目录、只读目录、权限拒绝（`chmod 000`，注意非 root 核验）、符号链接**启动或运行即拦截，且不偷偷创建目录或覆盖目标外文件。
- **清理断言三段式**：清理/过期删除测试必须按 **① 清理前断言目标真实存在且非空 → ② 执行清理 → ③ 断言目标清零且遍历零错误** 执行。
- **定时与时区边界**：周期/每日任务必测**停机跨过定时点后次日早于定时点重启补跑**、**跨午夜边界**与**夏令时跳钟**。

## 3. 黑盒 E2E 专项规则

- **并发隔离与动态端口**：端口用 `:0` 动态分配（若需预占后释放重绑须对 `EADDRINUSE` 做有限重试），目录与状态库一律用 `t.TempDir()`，确保 `t.Parallel()` 零端口/文件串扰。
- **外部代理做故障注入**：模拟 TCP 硬 `RST`（`SetLinger(0)`）、黑洞、限速或按帧改写时，在双端之间架轻薄 TCP 代理，不往生产代码里插测试后门。
- **只验真实外部产物**：黑盒 E2E 只校验真实落盘文件字节、持久化数据库状态与 `/metrics` 解析值；涉及重启续传的用例必须真关旧实例、拉新实例冷启动恢复。
- **禁长 `Sleep` 等就绪**：用带总超时的短轮询 `waitUntil` 或确定性 channel 信号等待状态收敛，不写固定长 `time.Sleep`。

## 4. 高危改动后的测试复核工作流

- 涉及复杂状态机、并发锁、持久化恢复或网络协议改动时，写完自测并通过 `-race -count=2` 后，建议拉起一次**独立只读 Review**，专门从上述六维反查“哪些入口路径、物理尺度或兜底掩护还没测到”。
